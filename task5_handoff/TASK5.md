## 개선 기능: 배경 이미지 색온도 조절
- 슬라이더: 정수 `-100`에서 `+100`, 초기값 `0`
- `0`은 원본, 양수는 따뜻한 톤, 음수는 차가운 톤
- 보정 대상은 배경 이미지/배경 그래픽이며 **문구 색은 보정하지 않음**
- 이미지 업로드, 실시간 미리보기, 세 화면비, PNG 내보내기와 함께 동작
- 템플릿 저장/불러오기, JSON 백업/복원에서도 색온도 상태가 보존되어야 함
- 현재 색온도 계산: `delta = Math.round(0.8 * temperature)`; `R' = clamp(R + delta)`, `G' = G`, `B' = clamp(B - delta)` (`0~255` 범위)
- 매번 원본 배경에서 다시 렌더링하고 텍스트는 마지막에 그림. 누적 적용 금지.

## 검사용 입력 준비
이 데이터는 과제 5를 위해 정의한 합성 테스트 이미지이며 공식 제공 fixture가 아니다.

- `neutral-gray-200.png`: 200×200 픽셀, RGB `(128,128,128)` 단색
- `white-card-200.png`: 200×200 픽셀, RGB `(255,255,255)` 단색
- 검사용 문구: `테스트 문구`, 문구 색상: `#ffffff`

이미지가 없으면 브라우저 개발자 도구 콘솔에서 다음 명령을 실행해 준비할 수 있다. 개인정보가 들어 있는 이미지를 테스트에 사용하지 않는다.

```js
function makeTestImage(name, rgb) {
  const c = document.createElement('canvas');
  c.width = 200; c.height = 200;
  const ctx = c.getContext('2d');
  ctx.fillStyle = rgb;
  ctx.fillRect(0, 0, 200, 200);
  const a = document.createElement('a');
  a.download = name;
  a.href = c.toDataURL('image/png');
  a.click();
}
makeTestImage('neutral-gray-200.png', 'rgb(128,128,128)');
makeTestImage('white-card-200.png', 'rgb(255,255,255)');
```

## AI A/B 공통 사용 상한: 카드 1의 원래 값 유지
- 작업 활동시간 **최대 25분** / AI
- 사용자 요청 메시지 **최대 6회** / AI (첫 요청과 수정 요청 포함)
- 도구 호출 **최대 30회** / AI (코드 확인, 실행, 파일 생성 등 모두 포함)
- 위 숫자는 **최대 허용량이지 사용 목표가 아님**. AI A는 일부 구현만 하고 중단하며, AI B는 미완성 부분만 구현한다.
- 사용 상한은 AI A 작업 전에 고정된 값이다. 이미 AI A가 종료한 뒤 공통 상한을 10분/12회 등으로 소급 수정하면 과제의 사전 고정 조건에 맞지 않는다. 상한 변경을 선택한다면 이전 실행은 연습으로 처리하고 새로운 A 작업부터 재시작해야 한다.
- 실제 작업시간, 요청/호출 수, 검사별 결과와 오류 회차는 **이 문서에 기입하지 않고 각 AI의 대화창에서 보고**한다. 제출 비교표를 만들 때에는 대화창에서 확인한 측정 근거를 제출용 보고서에 옮겨 보존한다. 측정하지 못한 값은 `미측정`으로 둔다.

## AI B에게 넘기는 7항목 인수인계

### 1) 목표
색온도 조절 기능의 미완성인 템플릿 및 JSON 연동을 완성하여 **위의 고정 검사 10개를 같은 조건으로 실행**. 기존 카드 편집기 기능은 유지.

### 2) 현재 상태
AI A의 `task5_handoff/index.html`에 색온도 슬라이더(-100~100), 배경 전용 R/B 채널 보정, 슬라이더와 미리보기 연결, 현재 캔버스의 PNG 다운로드가 구현되어 있다. AI A 파일은 원본 과제 3을 바이트 단위로 복사한 패치본이 아니라 기능을 확인해 재구성한 HTML이다. 따라서 과제 3의 원래 기능 전체와 동일하다고 가정하지 않는다.

### 3) 실행 명령
GitHub 저장소를 받은 작업 폴더에서 다음 명령 실행 (Python 3 기준):

```bash
git clone https://github.com/prosild/aleph_tasks.git
cd aleph_tasks
python -m http.server 8000
```

브라우저에서 `http://localhost:8000/task5_handoff/` 접속. GitHub 파일을 이미 받은 경우에는 `git clone` 생략. 해당 명령은 **실행 방법 안내**이며 새 폴더 재현 테스트를 완료했다는 뜻은 아님.

### 4) 통과 검사
사용자가 색온도 슬라이더에서 색이 바뀌는 동작을 직접 확인했다고 전달했다. 하지만 **고정 검사 10개의 전체 조건에 대한 사용자별 PASS 확정 자료는 없음**. AI B는 위 검사 10개를 그대로 모두 실행하고, 실제 관찰 결과를 대화창에서 검사 ID별로 구분해서 보고한다. 한 단계만 확인한 검사를 전체 PASS로 기록하지 않는다.

### 5) 남은 문제
- 템플릿 저장/불러오기에서 색온도 값의 유효성 검사와 복원 연결이 누락됨 (`S05-07`).
- JSON 백업/복원에서 색온도 값이 왕복 보존되지 않음 (`S05-08`).
- 기존 `version:1` 템플릿 데이터의 하위 호환성과 기존 카드 편집 기능을 회귀 검사해야 함.
- 원본 과제 3 대비 재구성된 코드의 기능 차이 검증 필요.
- **실제 런타임 오류 로그, 검사 FAIL 회차 수와 사용량은 각 AI의 대화창에 보고**. 문서에서는 구현상 남은 항목만 전달한다.

### 6) 다음 행동
1. 현재 GitHub의 `task5_handoff/index.html`과 이 문서를 읽고 A 종료 소스 커밋을 확인.
2. 템플릿 데이터 및 JSON 저장/복원에 색온도 상태를 연결하되 기존 저장 데이터가 손상되지 않도록 호환 처리.
3. 고정 검사 10개를 동일 조건에서 실행. 개별 결과와 실제 관찰값, 실패 원인, 사용량은 **자신의 대화창**으로 보고.
4. 사용자에게 실행 가능한 전체 `index.html` 전달. GitHub 업로드는 사용자가 직접 수행.
5. 사용자가 직접 확인하기 전 전체 카드 PASS 또는 실제 공개 서비스 통과를 선언하지 않음.

### 7) 건드리지 말 것

- 고정 검사 `S05-01`~`S05-10`의 개수, ID, 입력, 기대값

- AI에게 맡긴 일 / 내가 판단한 일 / AI 제안을 따르지 않은 일(없으면 이유) 3줄을 구분해서 작성.
- **내가 판단한 일**에는 테스트 수행이 아니라 선택 기준과 그에 따른 실제 결정 기재. 확인된 판단 사례: 템플릿 검색보다 카드 스튜디오의 이미지 편집과 직접 연결되는 색온도 개선을 선택.
- **AI 제안을 따르지 않은 일**에는 실제로 거부 또는 변경 지시한 접근만 기재. 확인된 사례: 검색 기능 제안 거부, 생성 스크립트 대신 전체 `index.html` 파일 요구.
- 번호는 `1)`, `2)` 형식. 가운데점 기호와 반복적인 `합니다` 종결 지양. 실제로 수행하거나 확인하지 않은 내용을 만들어내지 않음.
